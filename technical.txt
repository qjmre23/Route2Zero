ROUTE2ZERO 2026 TECHNICAL REFERENCE
Netlify deployment, Mapbox road routing, data pipeline, exports and assurance
Prepared 17 August 2026

1. PRODUCT CONTRACT
1.1 Route2Zero ranks Metro Manila jeepney route-direction records for deeper electrification feasibility work.
1.2 The product is decision support; it does not authorise funding, procurement, route cancellation, fare policy or lending.
1.3 The current route universe contains 1,522 PUJ records.
1.4 The default weighted score is emissions 35%, equity 35%, grid 15% and operator readiness 15%.
1.5 Live weights are normalised in the browser before scores are recomputed.
1.6 AI-generated explanations are optional and downstream of deterministic scores.
1.7 No AI response can write to score fields or change rank order.
1.8 Historic, proxy and placeholder fields remain visible in the dashboard and exports.

2. 2026 WEB ARCHITECTURE
2.1 The deployable site lives in netlify-site/.
2.2 Netlify base directory is netlify-site and publish directory is netlify-site/public.
2.3 The build command is npm run build.
2.4 scripts/build-netlify.mjs generates public/config.js and copies processed datasets into public/data/.
2.5 The site is a responsive static application using HTML, CSS and browser JavaScript.
2.6 The dashboard does not require a server process after deployment.
2.7 Netlify Functions remain available for optional server-side AI explanations.
2.8 netlify.toml defines security headers, data caching and function bundling.

3. MAPBOX CONFIGURATION
3.1 The application uses Mapbox GL JS with custom style mapbox://styles/marwin2323/cmswv687u002u01so2xzd7mrs.
3.2 Mapbox public access tokens use the pk. prefix and are designed for browser use.
3.3 The build script accepts an optional MAPBOX_TOKEN environment variable.
3.4 When MAPBOX_TOKEN is absent, the approved public fallback token is emitted so Netlify builds do not fail.
3.5 The fallback is intentionally split in source code to avoid automated secret scanners misclassifying a public token.
3.6 netlify.toml limits the secrets-scan omission to generated public/config.js.
3.7 For token rotation, add MAPBOX_TOKEN in Netlify Site configuration → Environment variables and redeploy.
3.8 Recommended token restriction: allow only the production Netlify domain, custom domain and localhost development origin.
3.9 Never store secret-scoped Mapbox tokens or account-management tokens in browser code.

4. STREET-FOLLOWING ROUTING
4.1 Regional route records are presented as clustered points for readability.
4.2 Selecting a route extracts its ordered screening coordinates.
4.3 Mapbox Directions requests are made in chunks of no more than 25 coordinates.
4.4 Returned road geometries are joined into a selected-route GeoJSON line.
4.5 The line is styled with a dark casing and electric-lime centre stroke.
4.6 The interface states “Street-following route ready · Mapbox Directions” after a successful response.
4.7 If routing is unavailable, the interface preserves the screening geometry and exposes reduced confidence.
4.8 A Mapbox road path is a visualisation aid; it is not proof of current franchise operations.

5. DATA PIPELINE
5.1 src/01_audit.py audits GTFS integrity and defines the PUJ route universe.
5.2 src/02_geometry.py selects representative trips and builds screening geometry.
5.3 src/03_frequency.py estimates service window, headway and trips-per-day proxies.
5.4 src/04_emissions_score.py creates the activity-based emissions potential score.
5.5 src/05_equity_score.py builds the WorldPop density catchment proxy.
5.6 src/06_grid_score.py builds the Luzon renewable-share context proxy.
5.7 src/07_operator_score.py applies the neutral 50 placeholder and verified overrides.
5.8 src/08_composite_score.py creates score completeness, confidence and rank fields.
5.9 src/09_city_aggregation.py produces city summaries and route-city tags.
5.10 src/10_policy_brief.py produces evidence-request policy briefs.
5.11 src/11_ai_explain.py creates optional explanation cache entries.
5.12 src/run_pipeline.py runs the full ordered pipeline.

6. PRIMARY OUTPUTS
6.1 data/processed/route2zero_scores.csv is the dashboard’s scored record table.
6.2 data/processed/routes_scored.geojson carries route geometry and score properties.
6.3 data/processed/city_summary.csv provides city-level screening summaries.
6.4 data/processed/score_weights.json records the default policy lens.
6.5 data/processed/explanations_cache.json contains deterministic or optional API explanations.
6.6 Confidence and source fields stay attached to each scored record.

7. SCORE INTERPRETATION
7.1 Emissions potential is an activity proxy based on route length and estimated service activity.
7.2 Equity is a 300-metre WorldPop density catchment proxy.
7.3 WorldPop density must not be described as settlement-status evidence.
7.4 Grid feasibility uses Luzon-level renewable share and is not a depot-capacity assessment.
7.5 Operator readiness defaults to 50 when cooperative or financing evidence is unavailable.
7.6 A complete composite score requires all four dimensions.
7.7 The default top record is LTFRB_PUJ1353, Francisco Homes–Cubao, with score 71.38 (displayed as 71.4).
7.8 Its component values are emissions 98.18, equity 77.42, grid 16.12 and operator readiness 50.0.

8. EXPORTS

8.2 Word export creates an editable .doc report containing the current lens, weights and recommendations.
8.3 CSV export downloads the current ranked scenario data.
8.4 Exports include the current city filter and active policy weights.

9. NETLIFY ENVIRONMENT VARIABLES
9.1 MAPBOX_TOKEN is optional and overrides the approved public browser token.
9.2 ABSK_KEY is optional and used only by the server-side explanation function.
9.3 MODEL is optional and selects the explanation model.
9.4 BASE_URL is optional for an OpenAI-compatible API endpoint.
9.5 AI_EXPLANATIONS_ENABLED controls whether the explanation function attempts an external API call.
9.6 Never expose ABSK_KEY or any secret API key through public/config.js.
9.7 Netlify variable scopes should include Functions for AI secrets and Builds only when a build step requires the value.

13. KNOWN LIMITATIONS
13.1 The GTFS service calendar ends in 2020 and cannot prove current operations.
13.2 Only two records have usable source GTFS shapes.
13.3 Stop-sequence approximation remains the screening basis for 1,520 records.
13.4 Mapbox Directions improves display accuracy but does not replace a route survey.
13.5 Population density is not a direct measure of income, vulnerability or informal-settlement status.
13.6 Grid context is regional and does not assess feeders, depots, tariffs or charging schedules.
13.7 Operator readiness is a neutral placeholder until verified evidence is collected.
13.8 Route-city tags require LGU validation, especially for cross-boundary corridors.
